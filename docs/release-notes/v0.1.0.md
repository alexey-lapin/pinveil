pinveil 0.1.0 is a rewrite in Rust: a single static server binary, a `pinveil` CLI, and a
browser UI with no build step. See the [README](https://github.com/alexey-lapin/pinveil#readme)
to get started and the [operator guide](https://github.com/alexey-lapin/pinveil/blob/v0.1.0/docs/operator-guide.md)
to run a server.

## Upgrading from 0.0.x

Nothing carries over from the Java server.

- Settings moved from `APP_*` environment variables to `PINVEIL_*`, with `__` between section
  and key, and some moved to a different section. Unknown `PINVEIL_` keys stop the server, but
  the old `APP_*` names are simply ignored, so rename them before you upgrade:

  | 0.0.x | 0.1.0 |
  |---|---|
  | `APP_MESSAGES_PIN_PEPPER` | `PINVEIL_PIN__PEPPER` |
  | `APP_MESSAGES_MAX_FAILED_PIN_ATTEMPTS` | `PINVEIL_PIN__MAX_FAILED_ATTEMPTS` |
  | `APP_MESSAGES_MAX_STORED_MESSAGES` | `PINVEIL_STORE__MAX_MESSAGES` |
  | `APP_MESSAGES_MAX_STORED_BYTES` | `PINVEIL_STORE__MAX_BYTES` |
  | `APP_MESSAGES_MIN_TTL`, `_MAX_TTL`, `_DEFAULT_TTL`, `_TTL_PRESETS` | `PINVEIL_MESSAGES__MIN_TTL`, `__MAX_TTL`, `__DEFAULT_TTL`, `__TTL_PRESETS` |
  | `APP_MESSAGES_MAX_PAYLOAD_BYTES` | `PINVEIL_MESSAGES__MAX_PAYLOAD_BYTES` |
  | `APP_MESSAGES_PBKDF2_ITERATIONS` | `PINVEIL_MESSAGES__PBKDF2_ITERATIONS` |
  | `APP_RATE_LIMIT_WINDOW` | `PINVEIL_RATE_LIMIT__WINDOW` |
  | `APP_RATE_LIMIT_CREATE_REQUESTS_PER_WINDOW` | `PINVEIL_RATE_LIMIT__CREATE_PER_WINDOW` |
  | `APP_RATE_LIMIT_RETRIEVE_REQUESTS_PER_WINDOW` | `PINVEIL_RATE_LIMIT__RETRIEVE_PER_WINDOW` |

  New in 0.1.0: `PINVEIL_SERVER__TRUSTED_PROXIES`. 0.0.x trusted `X-Forwarded-For` from
  anyone; 0.1.0 trusts it only from the proxies you list.
- The image is built `FROM scratch` and runs as UID 65532. A volume mounted at `/data` for the
  SQLite store must be writable by that user.
- Unread messages in the 0.0.x in-memory store are lost on upgrade, and links made by 0.0.x
  can't be opened by 0.1.0.
